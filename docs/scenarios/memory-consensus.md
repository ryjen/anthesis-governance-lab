# Forged reasoning precedent and memory consensus (#81)

Six synthetic no-effect scenarios model stored reasoning **summaries**, never private chain-of-thought. The fixture keeps the memory record, host-owned producer/source/write-channel, payload claim, trusted-run evidence identities and counts, consensus profile, candidate learning, consuming task-context revision, and promoted guidance separate. Each positive synthetic reference has a unique run ID, evidence ID, integrity-bound marker, and verifier label. Candidate lessons carry detector, revision, input-record, and candidate IDs. The mixed-history case preserves explicit conflicting-claim IDs.

The malicious cases model unsupported prior validation, forged `source=agent` claims, and correlated repeated false precedent. The detector case keeps an anomaly lesson as a candidate. Benign repeated evidence remains useful for candidate prioritization but does not automatically select trusted guidance. Mixed history preserves contradiction even when forged repetitions outnumber one host-observed run.

Run `bash scripts/validate-memory-consensus.sh` and `bash scripts/test-memory-consensus.sh`; the latter must reject 18 negative mutations. Both are part of the canonical external-security suite.

**Assurance limits:** All evidence references and host metadata are synthetic declarations. This validator checks a fixed expected shape and is not a memory service, dynamic consensus evaluator, host-derived provenance verifier, evidence integrity proof, self-modifying prompt system, or production runtime security gate. It does not validate actual run identities or promote any guidance. It executes no network or protected effects.
